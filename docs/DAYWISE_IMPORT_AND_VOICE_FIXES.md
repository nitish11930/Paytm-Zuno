## Report import
A small header Import payments action opens CSV import. It does not read the bank account or Soundbox device. Paytm merchant reports can be downloaded separately; official report field layouts vary, so the UI requires explicit column mapping and date format review. CSV only, 128 KB / 200 data rows per batch. ISO dates/timestamps with explicit offset, or selected Indian DD/MM/YYYY / DD-MM-YYYY date/time formats. Invalid/ambiguous dates, future rows, malformed amounts, conflicting references and refund/unknown statuses fail without partial import. Pending/failed rows are skipped visibly. A clearly synthetic demo template is provided.

Preview and commit are separate. Preview is frozen for ten minutes; commit is transactional, merchant scoped and replay safe. Imported records are self-supplied report evidence, not independently verified payments. Transaction IDs are unique within merchant and record type. Changed details under the same reference conflict. Imported raw records and bank settlements do not alter money.

Each customer payment must be explicitly linked to a same-day/amount existing unreversed UPI entry, or classified as sale / linked collection / other receipt. New records require merchant confirmation that money was received/settled and not already included in entries or opening balance. Same-amount/date UPI matches require link or explicit separate-payment confirmation; identity cannot be guessed from amount alone. One report payment per ledger link. Collections remain capped and scoped to an existing due, and cannot predate that due. Historical classification keeps the original date. Settlements remain a separate reference category and are never income again. Reversal marks the linked imported record as reversed; silent reclassification is not allowed. Reports, batches and links are in complete export/reset.
